## Product objective

Build one local workspace where the owner can create, edit, inspect, undo, reopen, play and export their work, with assistance grounded in authorized evidence. PLATZ Core owns canonical state and typed edits. Studio owns the authoring interface and Runtime will play pinned snapshots. ATLAS reads authorized evidence and proposes a change through the same typed operation that manual editing uses. The trusted host controls scope and commits. GF-001 exercised editing and persistence (U0/U1). GF-002 added OpenGL compatibility and Vulkan validation. GF-003 adds the authorized evidence lookup. GF-004 can stage a temporary viewport preview of one proposed light change.

## Decisions that affect future work

- 2026-11-19. Windows-first .NET 10 and WPF use the local Desktop SDK. Canonical project data lives in Core and the UI consumes a renderer-neutral snapshot. Renderer resources and the active backend remain local to presentation code. This keeps project edits and recovery available without model or renderer availability.
- 2026-11-19. Use the public museum fixture as the initial living validation scene. Each run uses a writable copy outside source so owner work and test output cannot change the fixture. Add the independent fresh-project workflow as Hub and authoring deepen.
- 2026-11-19. Schema 1 is a checksummed JSON envelope with stable IDs, normalized top-left coordinates and typed light history. Core flushes same-directory staging before replacing the head and retains one previous saved artifact. The bundled fixture is protected by its reserved project identity. The preview consumes a renderer-neutral triangle snapshot. Canonical PBM asset validation is in place and texture presentation is future scope.
- 2026-11-19 (GF-002). OpenGL 3.3 Core compatibility (`OpenGlViewport`) uses Win32/WGL/OpenGL P/Invoke directly in `PlatzAtlas.Rendering` without extra NuGet dependencies, matching top-left normalized coordinates (`1.0 - position.y * 2.0`) and UNORM sRGB output. Runtime backend selection cascades `Vulkan -> OpenGL -> CPU Reference`, recreating the child `HwndHost` (`ReleaseNative`) across backend switches so Win32 `SetPixelFormat` and Vulkan surface lifetimes stay isolated. Vulkan validation instrumentation attaches `VK_EXT_debug_utils` (`InstanceCreateInfo.PNext` + `vkCreateDebugUtilsMessengerEXT`) across full instance/device/swapchain/surface lifetimes when `PLATZ_ATLAS_VK_VALIDATION=1`.
- 2026-11-19 (GF-003). Studio holds an ephemeral read grant for one project, scene and saved revision. The gate checks scope, grant and operation profile before calling the source. The deterministic resolver follows the switch target ID in a bounded version-1 JSON envelope. Studio uses an in-process byte handoff and the contract tests verify the same bytes through a file. Owner-facing export/import and cross-process transport remain future scope. The writable project schema and dependencies are unchanged.
- 2026-11-19 (GF-004). The owner explicitly stages a proposal from the current issued answer. ATLAS derives the switch ID, object ID and old and new values. Core validates the typed operation and compares the saved file fingerprint before projecting a detached lantern state. Only the render snapshot uses the draft value. Write approval and publication are future scope. Studio checks disk freshness at staging time, and ordinary edits immediately retire the grant.
